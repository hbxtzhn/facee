## 题目
不使用 `java.util.concurrent` 中现成的阻塞队列，实现 `BoundedQueue<T>`：

- `put(T)`：队列满时阻塞；
- `take()`：队列空时阻塞；
- 支持多个生产者与多个消费者并发调用。

## 一句话
用一把锁保护环形数组，并用「不满」「不空」两个条件分别让生产者和消费者等待，条件判断放在 while 循环里。

## 要点
- [kp1|3] 共享状态的读写必须在同一把锁内完成
- [kp2|3] 等待条件必须用 while 循环判断，防止虚假唤醒
- [kp3|2] 用两个 Condition 分开唤醒生产者与消费者，避免无效唤醒
- [kp4] 若用 synchronized + wait / notify，要用 notifyAll

## 详解
### 为什么用 while 而不是 if
线程被唤醒后需要重新竞争锁，期间条件可能又被其他线程改变；JVM 也允许虚假唤醒。因此醒来后必须重新检查条件。

### 为什么用两个条件
若生产者和消费者在同一个条件上等待，`signal` 可能唤醒同类线程（例如生产者唤醒了另一个生产者），导致所有线程都在等待。拆成 `notFull` 与 `notEmpty` 后，每次只唤醒真正能继续执行的一方。

### 用 synchronized 实现
只有一个等待集合，必须 `notifyAll()`，否则可能出现上面的「唤醒错对象」问题。

## 示例
```java
public class BoundedQueue<T> {
    private final Object[] items;
    private int head, tail, count;
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition notFull = lock.newCondition();
    private final Condition notEmpty = lock.newCondition();

    public BoundedQueue(int capacity) { items = new Object[capacity]; }

    public void put(T item) throws InterruptedException {
        lock.lockInterruptibly();
        try {
            while (count == items.length) notFull.await();
            items[tail] = item;
            tail = (tail + 1) % items.length;
            count++;
            notEmpty.signal();
        } finally {
            lock.unlock();
        }
    }

    @SuppressWarnings("unchecked")
    public T take() throws InterruptedException {
        lock.lockInterruptibly();
        try {
            while (count == 0) notEmpty.await();
            T item = (T) items[head];
            items[head] = null; // 帮助 GC
            head = (head + 1) % items.length;
            count--;
            notFull.signal();
            return item;
        } finally {
            lock.unlock();
        }
    }
}
```

## 易错点
- 用 if 判断条件，被虚假唤醒后越界读写
- 在锁外调用 await / signal，抛出 IllegalMonitorStateException
- 出队后不清空数组槽位，导致对象无法被回收

## 追问
### [f1] 和 ArrayBlockingQueue 的实现有什么不同？
思路基本一致：ArrayBlockingQueue 同样是一把 ReentrantLock 加 notEmpty / notFull 两个条件。它还提供 offer / poll 的超时版本、可选的公平锁，以及迭代器等完整的集合接口。
