## 题目
商品详情接口采用「先查 Redis，未命中再查 MySQL 并回填」的旁路缓存。大促期间数据库 CPU 突然打满，请分析三类缓存失效问题的成因与对策。

## 一句话
穿透是查不存在的数据，击穿是单个热点 key 过期，雪崩是大量 key 同时失效或缓存宕机，三者都让请求直达数据库。

## 要点
- [kp1|2] 穿透：缓存空值或用布隆过滤器拦截不存在的 key
- [kp2|2] 击穿：热点 key 用互斥锁重建，或逻辑过期后异步刷新
- [kp3|2] 雪崩：过期时间加随机偏移，并保证缓存集群高可用
- [kp4] 兜底：限流、降级与熔断，保护数据库

## 详解
### 缓存穿透
请求的数据在缓存和数据库中都不存在（如 id = -1 的恶意请求），每次都会打到数据库。

- 缓存空对象：数据库查不到时也写一个短 TTL 的空值；
- 布隆过滤器：预先放入全部合法 id，判断「一定不存在」时直接返回。布隆过滤器有误判（说存在但其实不存在），但不会漏判。

### 缓存击穿
某个高并发访问的热点 key 恰好过期，大量请求同时回源。

- 互斥锁：只有拿到锁（如 `SET lock NX PX 3000`）的请求查库重建，其余等待或返回旧值；
- 逻辑过期：key 不设 TTL，值里存过期时间，发现过期后由一个线程异步刷新，其余请求先返回旧值。

### 缓存雪崩
大量 key 在同一时刻过期，或 Redis 节点整体不可用。

- 过期时间 = 基础 TTL + 随机偏移；
- Redis 主从 + 哨兵或 Cluster，避免单点；
- 多级缓存（本地缓存 + Redis）。

## 易错点
- 把击穿与穿透混淆：击穿的数据是存在的
- 缓存空值不设过期时间，导致后来写入的真实数据长期读不到
- 以为布隆过滤器能判断「一定存在」

## 追问
### [f1] 布隆过滤器不支持删除，数据下线了怎么办？
可以定期全量重建布隆过滤器；或改用计数布隆过滤器、布谷鸟过滤器（Cuckoo Filter）这类支持删除的结构。误判只会让少量请求回源，不影响正确性。

### [f2] 互斥锁方案中，拿不到锁的请求怎么处理？
短暂休眠后重试读缓存，或直接返回旧值 / 默认值。重试要设上限，避免线程堆积；锁要设过期时间，并只能由持有者释放（比较锁值后删除）。
