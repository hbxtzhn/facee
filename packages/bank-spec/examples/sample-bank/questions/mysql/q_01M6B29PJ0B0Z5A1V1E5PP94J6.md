## 一句话
四个级别依次是读未提交、读已提交、可重复读（InnoDB 默认）和串行化；InnoDB 用 undo log 版本链加 ReadView 实现快照读。

## 要点
- [kp1|2] 读未提交有脏读；读已提交解决脏读；可重复读解决不可重复读
- [kp2|3] 每行有隐藏列 DB_TRX_ID 与 DB_ROLL_PTR，旧版本串在 undo log 版本链上
- [kp3|3] ReadView 判断版本可见性：RC 每条语句新建，RR 事务首次读时创建
- [kp4|2] RR 下快照读靠 MVCC，当前读靠 next-key lock 防止幻读

## 详解
### 隔离级别与现象

| 级别 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|
| READ UNCOMMITTED | 可能 | 可能 | 可能 |
| READ COMMITTED | 否 | 可能 | 可能 |
| REPEATABLE READ | 否 | 否 | InnoDB 大部分情况可避免 |
| SERIALIZABLE | 否 | 否 | 否 |

### ReadView
ReadView 记录创建时的活跃事务 id 列表 `m_ids`、最小活跃 id `min_trx_id`、下一个将分配的 id `max_trx_id`，以及创建者 `creator_trx_id`。判断某版本的 `DB_TRX_ID`：

- 等于 `creator_trx_id`：自己改的，可见；
- 小于 `min_trx_id`：创建 ReadView 前已提交，可见；
- 大于等于 `max_trx_id`：之后才开启，不可见；
- 在两者之间：在 `m_ids` 中则未提交、不可见，否则可见。

不可见就沿 `DB_ROLL_PTR` 找上一个版本，直到可见或链尾。

### 快照读与当前读
普通 `SELECT` 是快照读，读 ReadView 可见的版本；`SELECT … FOR UPDATE`、`UPDATE`、`DELETE` 是当前读，读最新版本并加锁。

## 示例
```sql
SELECT @@transaction_isolation;
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

## 易错点
- 以为 MVCC 能单独解决所有幻读；当前读要靠 next-key lock
- 以为 RR 的 ReadView 在 BEGIN 时创建；实际在第一次快照读时创建
- 把 undo log 当成 redo log：undo 用于回滚与 MVCC，redo 用于崩溃恢复

## 追问
### [f1] RR 级别下还会出现幻读吗？举个例子。
会。事务 A 先快照读得到 0 行；事务 B 插入一行并提交；A 再执行 `UPDATE` 命中这一行（当前读），此后 A 的快照读也能看到它，因为该行版本的 trx_id 变成了 A 自己。

### [f2] 想让 RR 事务从 BEGIN 就固定快照怎么办？
使用 `START TRANSACTION WITH CONSISTENT SNAPSHOT`，开启事务时立即创建 ReadView。
