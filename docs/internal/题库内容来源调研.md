# 题库内容来源调研（真题灌入可行性）

> 目的：在做之前把「能不能用、能用多少、怎么改才安全」查清楚。
> 结论先行：**可以做，但必须改写；许可证是分水岭，且"看 license 字段"不够。**

---

## 一、结论摘要

| 问题 | 结论 |
|---|---|
| GitHub 上有多少可用素材？ | 很多，但**许可证干净的中文题库只有少数几个** |
| 有没有可直接拿来用的？ | **没有**。最理想的中文源（`doocs/advanced-java`）**上游权利有瑕疵**，必须绕开 |
| 能不能"原封不动上传"？ | **不能**，也不建议轻微改写 —— 法律看"实质性相似"，改几个词照样侵权 |
| 可行且安全的路子 | **只取题目方向/知识点（事实性内容），答案 100% 原创**，并用**相似度指标**证明原创 |
| 建议首期规模 | **150 题**（11 个方向，含约 30 条追问），一天内可交付 |

## 三、法律要点（这次调研最关键的产出）

1. **许可证只覆盖作者真正拥有的部分。** `advanced-java` 是活标本：标了 CC-BY-SA，却在 README 里承认内容来自第三方课程。所以尽职调查**必须看 README 的来源声明**，不能只看 license 字段。

2. **不同许可对我们的约束不同：**

   | 来源许可 | 我们能做什么 | 对我们的传染 |
   |---|---|---|
   | MIT / Apache-2.0 | 可商用、可改编 | 需**保留版权声明与 NOTICE**（署名即可），不传染题库许可 |
   | CC-BY-SA-4.0 | 可改编 | **要求我们的题库也 CC-BY-SA**（相同方式共享，传染） |
   | GPL-3.0 | 理论可 | 传染性最强，**避开** |
   | 无许可证 | **什么都别做** | —— |

3. **"别原封不动"在法律上不足以保证安全。** 判定侵权看的是**实质性相似**：把「是什么」改成「何为」、调整语序、删几句，仍然可能构成演绎侵权。
   真正安全的做法是：**只取"题目方向/知识点"这类事实性、不受版权保护的要素，答案与表述完全由我们原创。**

4. **题目标题本身**：短问句、通用技术提问（如「HashMap 的底层结构」）属事实性表达，版权保护很弱；但**整份"精心编排的选题集合"**可能作为汇编作品受保护。→ 所以我们的选题要**跨多个来源 + 结合技术栈覆盖度自行补题**，而不是照搬某一个库的目录结构。

## 四、三个候选方案

| 方案 | 做法 | 法律风险 | 内容质量 | 工作量 |
|---|---|---|---|---|
| **A 忠实改编** | 拆 `JavaGuide`（Apache-2.0）+ 少数 MIT 仓，答案精简/改写，保留署名 | 中（Apache 允许，但需署名；改编边界仍需谨慎） | 高 | 小 |
| **B 题目方向 + 原创答案**（推荐） | 只抽取**题目/知识点清单**，答案、标签、难度、追问、结构**全部原创**；加**相似度门槛**做证明 | **低** | 中-高 | 大 |
| **C 完全自创** | 不参考任何仓库，按技术栈覆盖度出题 | 极低 | 中（可能与真实面试热点偏离） | 大 |

**推荐 B**，理由：既满足你"别原封不动"的要求，又能借公开库保证**选题覆盖度贴近真实面试**，同时把法律风险压到最低。

## 五、方案 B 的执行流水线（机械部分可全自动）

```
1. 抓取：GitHub 归档 ZIP（不逐文件调 API）
   → 只用于「抽取题目清单」；正文仅作我写答案前的背景阅读，不进入题库

2. 抽题：按标题/编号切分 → 归一化
   去序号、去 emoji、去「面试题：/面试官：」前缀、统一问号、剔除纯目录/大纲条目

3. 去重：跨源语义去重（标题 trigram + 关键词），同义题合并、保留覆盖面更广的表述

4. 选题：结合技术栈覆盖度**自行补充**题目，不照搬任何单一仓库的目录结构
   目标分布：Java 基础 / JVM / 并发 / 集合 / Spring / MySQL / Redis / MQ / 网络 / 操作系统 / 分布式

5. 写答案（★核心工作量）：全部原创，每题 300–800 字，含代码块/表格；
   约 20% 的题配「面试官追问」（2–3 条 followups.md）

6. 标元数据：分类 categoryId、标签（映射到我们的标签树）、难度（简 30% / 中 50% / 难 20%）、order

7. 生成：用 packages/bank-spec 生成 catalog.json + questions/<id>/{question.md,answer.md,followups.md,assets}

8. 双重校验：
   a) bank-spec --verify 必须 0 error
   b) ★ 相似度检查：每题正文 vs 来源语料的 trigram 重合率 / 最长公共子串占比，
      输出 max_similarity，超过阈值（建议 15%）即重写

9. 交付：推 facee-bank + 更新 Release（纯净 question-bank.zip）+ 附相似度报告与 sources.md
```

**第 8b 步是这次方案的关键**：把"不是原封不动"变成**可测量的指标**，而不是我的口头保证。交付时我会附一张表：每道题的相似度、最高值、阈值内的题数。

## 七、我明确**不会**做的事

1. **不复制任何源的正文**（答案全部原创，且用相似度指标自证）
2. **不使用无许可证的仓库**（`CyC2018/CS-Notes`、`AobingJava/JavaFamily`、`0voice/*` 等一律不碰）
3. **不使用 GPL 来源**（避免传染）
4. **不引入 CC-BY-SA 传染**：`advanced-java` 即使技术上最省事，也不采用
5. **不照搬任何单一仓库的选题结构**（跨源 + 自行补充，避免汇编作品风险）
6. **不把来源正文放进仓库**（只在 `sources.md` 里列出"题目方向参考了哪些公开仓库 + 许可证"）
