# FaceE 题库规范 v2（草案）

> 状态：**已定稿，实现中**（2026-11-05；2026-11-08 按题库仓库提案修订：标签说明与别名、每题 1–3 个标签、难度语义、核心要点上限、contentHash 只算内容字段、日常校验与发版构建分开）。决议见 §8。
> 前提：现有题库全部弃用重建，**不兼容 v1、不做数据迁移**；v2 App 不读取旧版 App 的任何本地数据（本地题库、收藏、掌握度、复习记录均从零开始）。
> 取代：[`题库规范-v1.md`](./题库规范-v1.md)（v2 落地后 v1 与 ZIP 目录形态一并下线）。

## 0. 设计原则

1. **三层分离**：作者编写格式、对外分发格式、App 内部存储各用最合适的形态，互不绑定。
2. **结构在数据里，Markdown 只在字段里**：App 不解析 Markdown 标题来推断「哪段是答案、哪段是追问」。
3. **身份永久**：题库 id、题目 id、要点 id、追问 id 发布后永不改变、永不复用；学习数据只挂在这些 id 上。
4. **题库只读，学习数据独立**：更新题库只替换题库数据，收藏 / 掌握度 / 自评 / 笔记永远不受影响。
5. **检查更新要轻**：只拉几 KB 的清单，不依赖 GitHub API，可走镜像。

| 层 | 使用者 | 形态 |
|---|---|---|
| 编写格式（§2） | 题库作者，git 仓库 | 每题一个 Markdown 文件（YAML front matter + 固定分段） |
| 分发格式（§3） | App 下载 | 编译生成的 `bundle.json` + 资源文件 + `latest.json` |
| 存储格式（§6） | App 运行时 | SQLite；题库表与学习数据表分离 |

编写格式 → 分发格式由构建工具（`packages/bank-spec`）完成；分发格式 → 存储格式由 App 安装器完成。**分发格式是唯一的对外契约**，存储格式是 App 内部实现，可随 App 版本调整而无需重新发布题库。

## 1. 标识符

| 标识 | 格式 | 规则 |
|---|---|---|
| 题库 id `bank.id` | `<host>/<owner>/<repo>`，如 `github.com/hbxtzhn/facee-bank` | 全局唯一、永不改变；App **不得**改写 |
| 题目 id | `q_` + ULID，如 `q_01JC8ZQ4N3V6W8X0Y2Z4A6B8C0` | 由工具生成；**不得**从标题派生（标题会改） |
| 要点 id | 题内唯一，`kp1`、`kp2`… | 文字可改、id 不变；删除后不复用 |
| 追问 id | 题内唯一，`f1`、`f2`… | 同上 |
| 分类 / 标签 / 专题 id | `^[a-z0-9][a-z0-9-]{0,63}$` | 库内唯一 |

学习数据的主键：`(bank.id, question.id)`；要点自评再加 `keyPoint.id`，追问掌握再加 `followup.id`。

## 2. 编写格式（作者仓库）

```
<仓库根>/
├─ bank.yaml                     # 题库元数据、分类、标签、专题、生命周期
└─ questions/
   └─ redis/                     # 子目录仅用于作者组织，不参与语义
      ├─ q_01JC8ZQ4….md
      └─ assets/
         └─ expire-cycle.png
```

### 2.1 题目文件

````markdown
---
id: q_01JC8ZQ4N3V6W8X0Y2Z4A6B8C0
title: Redis 过期 key 的删除策略有哪些？
type: concept                   # concept | scenario | coding | design | behavioral | choice
difficulty: medium              # easy | medium | hard
importance: 3                   # 1–3，考察频率 / 核心程度
category: redis
tags: [redis, memory]           # 1–3 个，可跨分类
appliesTo: ["Redis >= 6"]
prerequisites: []
related: [q_01JC90AB…]
source: { name: 自整理, license: CC-BY-4.0 }
references:
  - { title: "Redis 文档：EXPIRE", url: "https://redis.io/docs/latest/commands/expire/" }
reviewedAt: 2026-11-05
estimatedMinutes: 3
---

## 题目
（标题之外的补充：场景、约束、给定代码。无补充时整段省略。）

## 一句话
惰性删除与定期删除组合清理过期 key。

## 要点
- [kp1|2] 访问 key 时检查是否过期（惰性删除）
- [kp2|2] 后台周期性抽样清理（定期删除）
- [kp3] 仍可能残留，最终靠内存淘汰策略兜底

## 详解
### 惰性删除
……

## 示例
```bash
redis-cli CONFIG GET hz
```

## 易错点
- 把过期删除与内存淘汰（LRU / LFU）混为一谈

## 追问
### [f1] 大量 key 同时过期会怎样？如何避免？
定期删除压力集中、CPU 抖动；给过期时间加随机偏移。
````

**front matter 约定**：

- `tags`：**必填，1–3 个**，必须在 `bank.yaml` 声明；按知识点打标签，可跨分类（如「持久化」同时用于 Redis 与 MySQL 的题）。分类 + 标签的组合即章节。
- `difficulty` 描述「回答要讲到多深」，与题型无关，任何题型都可以是 `hard`：

  | 取值 | 回答要讲清 |
  |---|---|
  | `easy` | 是什么、怎么用 |
  | `medium` | 工作机制、为什么这样设计 |
  | `hard` | 取舍与边界、源码或实现细节 |

- `importance`：1 = 一般，2 = 常见（默认），3 = 高频 / 核心；全库大致按 20% / 60% / 20% 分布。

**分段写法约定**（构建时强制校验）：

| 分段 | 必填 | 约束 |
|---|---|---|
| `## 题目` | ❌ | 不得重复标题；不得写出处（用 front matter `source`） |
| `## 一句话` | ✅ | 1–2 句，≤ 80 字 |
| `## 要点` | ✅ | 3–5 条；每条 `[id]` 或 `[id\|权重]` 开头，≤ 40 字；权重 1–3，默认 1；核心要点（`\|3`）每题最多 2 条（超出为警告） |
| `## 详解` | ❌ | 自由 Markdown，内部标题从 `###` 起；建议 ≤ 1500 字 |
| `## 示例` | ❌ | 代码块必须标语言，单块 ≤ 40 行 |
| `## 易错点` | ❌ | 无序列表 |
| `## 追问` | ❌ | 每条 `### [id] 问题`，答案 ≤ 150 字；需长篇展开的应升级为独立题并互相 `related` |
| `## 选项` | `type: choice` 时必填 | 见 §2.2 |

- 只允许以上二级标题，顺序固定，不允许一级标题。代码块内的 `#` 行不参与分段。
- 新建题、新增要点 / 追问时 id 留空，由 `bank-spec new` / `bank-spec fix-ids` 分配并回写，作者不手编 id。留空写法：要点 `- 文字`、`- [] 文字` 或 `- [|2] 文字`；追问 `### 问题` 或 `### [] 问题`。
- **字数**：非 ASCII 字符（汉字、全角标点）每个计 1，ASCII 字符（字母、数字、半角符号、空格）每个计 0.5，合计向上取整。
- **要点 / 追问 id 分配**：已有 id 永不改号；删除过的 id 记在 front matter `retired: [kp4, f2]`，永不复用；新 id = max(现有 ∪ `retired` 的编号) + 1。编号空洞（如有 kp1、kp3 而 `retired` 无 kp2）视为已删除，`validate` 报 `ID_GAP`，`fix-ids` 自动写入 `retired`。删除**编号最大**的一条时工具无法察觉，作者须手工把它加入 `retired`。`retired` 只用于编写，不进入 bundle。

### 2.2 选择题（预留）

```markdown
## 选项
- [a] Redis 只用惰性删除
- [b] Redis 只用定期删除
- [c] 两者结合 ✓
```

`✓`（或 `✔`）标记正确项，可多选；选项 id 为单个小写字母，至少 2 个选项、至少 1 个正确项。`## 详解` 作为解析：构建时写入 `choice.explanation`，`answer.detail` 为 `null`（不重复存放）；`## 一句话`、`## 要点` 仍然必填。

### 2.3 `bank.yaml`

```yaml
schemaVersion: 2
bank:
  id: github.com/hbxtzhn/facee-bank
  name: FaceE 面试题库
  version: 2.0.0               # SemVer；发布内容变化必须递增
  description: 全栈与 Agent 工程面试题库
  locale: zh-CN
  license: CC-BY-4.0
  homepage: https://github.com/HBxtzhn/facee-bank
  feedbackUrl: https://github.com/HBxtzhn/facee-bank/issues/new?template=content.yml&question={questionId}
  update:
    manifest: https://github.com/HBxtzhn/facee-bank/releases/latest/download/latest.json
    # fallback: 镜像地址（暂缓，见 §8）
categories:
  - { id: redis, name: Redis, order: 50 }
tags:
  - { id: redis, name: Redis, parent: null }
  - id: memory
    name: 内存
    parent: redis               # 建议最多两层（超出为警告）
    description: 过期删除、内存淘汰与内存占用；不含持久化   # 可选：范围说明，App 展示
    aliases: [内存管理]          # 可选：同义词，用于搜索与近义标签映射
collections:                    # 专题 / 学习路径：有序题单
  - id: redis-sprint
    name: Redis 3 天冲刺
    description: 高频核心题，按依赖顺序排列
    questions: [q_01JC8ZQ4…, q_01JC90AB…]
lifecycle:
  removed: []                   # 已删除的题目 id（永不复用）
  merged: {}                    # 旧 id → 并入的题目 id
release:                        # 可选；只写入 latest.json，不进入 bundle
  changes: 新增 Kafka 专题 20 题。 # → latest.json changes（纯文本），每次发版改写
  minAppVersion: 0.3.0          # → latest.json minAppVersion
```

- 题目的 `category` / `tags` 必须在此声明（上例为节选）；`tags[].parent` 省略时视为 `null`；分类、标签、专题保持 `bank.yaml` 中的书写顺序输出。
- 标签按知识点命名，不带分类前缀；层级建议最多两层（根 → 子），超过时 `validate` 报 `TAG_DEPTH` 警告。
- `tags[].description`：纯文本，一句话说明包括什么、不包括什么。
- `tags[].aliases`：非空字符串数组。别名在全库唯一（比较时忽略大小写与首尾空白），且不得与任何标签（含本标签）的 `id` / `name` 相同，否则报 `TAG_ALIAS_CONFLICT`。
- 专题（`collections`）是有序学习路线：一题可以出现在多条路线，可跨分类；同一路线内不得重复。

## 3. 分发格式

### 3.1 发布产物

```
dist/
├─ latest.json                  # 更新清单（§3.3），几 KB
├─ bundle-2.0.0.json            # 全部题库数据（§3.2）；不压缩，App 端无需引入解压库
└─ assets-2.0.0.zip             # 图片等资源，按 sha256 命名；无资源时省略
```

- 资源文件名为内容 sha256（如 `a3f2….png`），`bundle` 中引用该名字；同一资源跨版本不变则无需重复下载。
- ZIP 只装扁平的资源文件，不含目录与 Markdown，校验面远小于 v1。

### 3.2 `bundle.json`

```json
{
  "schemaVersion": 2,
  "bank": { "id": "github.com/hbxtzhn/facee-bank", "name": "…", "version": "2.0.0", "locale": "zh-CN",
            "license": "CC-BY-4.0", "homepage": "…", "feedbackUrl": "…", "update": { "manifest": "…", "fallback": "…" } },
  "categories": [ { "id": "redis", "name": "Redis", "order": 50 } ],
  "tags": [ { "id": "memory", "name": "内存", "parent": "redis", "description": "过期删除、内存淘汰与内存占用；不含持久化", "aliases": ["内存管理"] } ],
  "collections": [ { "id": "redis-sprint", "name": "…", "description": "…", "questions": ["q_…"] } ],
  "lifecycle": { "removed": [], "merged": {} },
  "questions": [
    {
      "id": "q_01JC8ZQ4N3V6W8X0Y2Z4A6B8C0",
      "title": "Redis 过期 key 的删除策略有哪些？",
      "type": "concept",
      "difficulty": "medium",
      "importance": 3,
      "categoryId": "redis",
      "tags": ["redis", "memory"],
      "appliesTo": ["Redis >= 6"],
      "prerequisites": [],
      "related": ["q_01JC90AB…"],
      "prompt": null,
      "answer": {
        "summary": "惰性删除与定期删除组合清理过期 key。",
        "keyPoints": [
          { "id": "kp1", "text": "访问 key 时检查是否过期（惰性删除）", "weight": 2 },
          { "id": "kp2", "text": "后台周期性抽样清理（定期删除）", "weight": 2 },
          { "id": "kp3", "text": "仍可能残留，最终靠内存淘汰策略兜底", "weight": 1 }
        ],
        "detail": "### 惰性删除\n……",
        "examples": "```bash\nredis-cli CONFIG GET hz\n```",
        "pitfalls": ["把过期删除与内存淘汰（LRU / LFU）混为一谈"]
      },
      "choice": null,
      "followups": [ { "id": "f1", "q": "大量 key 同时过期会怎样？如何避免？", "a": "……" } ],
      "source": { "name": "自整理", "license": "CC-BY-4.0" },
      "references": [ { "title": "Redis 文档：EXPIRE", "url": "https://redis.io/…" } ],
      "reviewedAt": "2026-11-05",
      "estimatedMinutes": 3,
      "contentHash": "sha256:…"
    }
  ]
}
```

- `prompt`、`detail`、`examples`、`followups[].a`、`choice.explanation` 为 Markdown 字符串；其余均为纯文本或结构化值。
- Markdown 子集：标题（`###` 起）、段落、强调、列表、引用、行内代码、带语言标注的代码块、表格、图片（`asset:<sha256>.<ext>`）、链接。**不支持 HTML**；Mermaid 等待 App 支持后再开放。
- `choice`：`{ "options": [{ "id": "a", "text": "…" }], "correct": ["c"], "explanation": "…" }`，仅 `type: choice` 时非空。
- `contentHash`：只对该题的**内容字段** `title`、`prompt`、`answer`（含要点 id 与权重）、`choice`、`followups` 计算；题型、难度、重要度、分类、标签、`appliesTo`、`prerequisites`、`related`、`source`、`references`、`reviewedAt`、`estimatedMinutes` 属于元数据，变化不改变 `contentHash`，App 也不会因此标记「内容已更新」（题库版本照常递增，App 照常提示更新）。精确定义：`"sha256:" + hex(SHA-256(UTF-8(canonical({ title, prompt, answer, choice, followups }))))`，其中 canonical 为：对象键按 UTF-16 码元升序、省略值为 undefined 的键、数组保持原序、字符串 / 数字 / 布尔 / null 按 `JSON.stringify` 输出、全程无空白（这些字段中只有字符串、整数与 null，结果与 RFC 8785 JCS 一致）。资源以 `asset:<sha256>.<ext>` 形式出现在 Markdown 字段里，因此图片内容变化必然改变 `contentHash`；文件改名、移动目录、题库元数据变化不影响它。
- 构建输出约定：`questions` 按 `id` 升序；`appliesTo` / `prerequisites` / `related` / `answer.pitfalls` 无内容时为 `[]`，`prompt` / `detail` / `examples` 无内容时为 `null`；`source` / `references` / `reviewedAt` / `estimatedMinutes` 无内容时省略；`importance` 缺省为 2，要点权重缺省为 1。
- 字段新增一律可选；App **忽略未知字段**。仅不兼容变更递增 `schemaVersion`，App 遇到更高的未知版本拒绝安装并提示升级。

### 3.3 `latest.json`

```json
{
  "bankId": "github.com/hbxtzhn/facee-bank",
  "schemaVersion": 2,
  "version": "2.1.0",
  "publishedAt": "2026-12-01T00:00:00Z",
  "minAppVersion": "0.3.0",
  "bundle": { "url": "…/bundle-2.1.0.json", "mirrors": ["…"], "sha256": "…", "size": 412345 },
  "assets": { "url": "…/assets-2.1.0.zip", "mirrors": ["…"], "sha256": "…", "size": 1048576 },
  "questions": { "q_01JC8ZQ4…": "sha256:…" },
  "changes": "新增 Kafka 专题 20 题；修正 Redis 过期策略要点。"
}
```

- App 检查更新只拉此文件：比较 `version`，再用 `questions` 与本地 `contentHash` 对比得出「新增 / 修改 / 删除」，更新前即可向用户展示。
- 下载的 `bundle` 与 `assets` 必须校验 `sha256` 与 `size`；`url` 失败按顺序尝试 `mirrors`。
- `minAppVersion`：App 低于该版本时提示先升级 App，不安装。
- 构建工具的生成规则：`changes` / `minAppVersion` 取自 `bank.yaml` 的 `release`（缺省则省略）；`url` = `--base-url`（缺省为 `bank.update.manifest` 所在目录）+ 文件名；`mirrors` 暂不生成（§8）；`publishedAt` 为构建时刻（UTC，精确到秒，可用 `--published-at` 固定）；`sha256` / `size` 针对写出的文件字节。

## 4. 题目生命周期

| 操作 | 作者做法 | App 行为 |
|---|---|---|
| 修改内容 | 直接改，`contentHash` 自动变化 | 学习数据保留；标记「内容已更新」，可提示重新复习 |
| 调整元数据（标签、难度、关系等） | 直接改 | 学习数据保留；不标记「内容已更新」 |
| 修改要点文字 | 保留 `[kpN]` id 改文字 | 自评记录保留 |
| 删除要点 / 追问 | 删除该条，id 不复用 | 对应自评记录归档 |
| 删除题目 | `bank-spec remove-question --id <旧>` | 隐藏题目；学习数据与笔记归入「已移除题目」，不丢弃 |
| 合并题目 | 先把旧题有价值的内容手工并入新题，再 `bank-spec merge-question --from <旧> --into <新>` | 学习数据迁到新题（冲突时取最近一次标记） |
| 题目 id 消失但未声明 | — | **构建失败** |

题目改名只改 `title`，id 不变，因此无需「重命名」声明。

删除与合并**必须**用上面两个命令，或手工完成同样的全部步骤（任何一步遗漏都会让构建失败或留下悬空引用）：

- `merge-question --from A --into B`：
  1. 所有题目的 `prerequisites` / `related` 中 A 改为 B；已含 B 或本题就是 B 时直接删掉 A（不产生重复与自引用）。
  2. 每条专题中 A 改为 B；专题已含 B 时直接删掉 A（B 保持原位置）。
  3. `lifecycle.merged` 中原本指向 A 的 `X: A` 改为 `X: B`（展开合并链，App 只需一跳），再写入 `A: B`。
  4. 改写后 `prerequisites` 成环则报错，不写任何文件。
  5. 删除 A 的题目文件。
- `remove-question --id A`：
  1. 所有题目的 `prerequisites` / `related` 与各专题中删除 A。专题因此变空时报错，需先手工处理该专题。
  2. 原本合并到 A 的 `X: A` 改记入 `removed`（目标已不存在）。
  3. 写入 `lifecycle.removed: [A]`，删除 A 的题目文件。
- 两个命令都支持 `--dry-run`，并且只在 YAML 节点范围内就地改写，保留文件其余内容与注释。

## 5. 构建与校验工具（`packages/bank-spec`）

| 命令 | 作用 |
|---|---|
| `bank-spec new` | 生成题目文件骨架并分配 ULID |
| `bank-spec fix-ids` | 为缺 id 的要点 / 追问补号并回写源文件 |
| `bank-spec validate` | 全量校验（下表）；CI 在 PR 上运行。给出 `--previous` 时另查 `bank.id` 不变与生命周期完整，**不要求**版本递增（普通 PR 不必升版本） |
| `bank-spec build` | 发版构建，生成 `dist/`。必须二选一：`--previous <上一版 latest.json>`（另要求版本递增）或首发时显式 `--first-release`；拿不到上一版时不得当作首发 |
| `bank-spec stats` | 全库报告：分类 / 题型 / 难度 / 重要度分布，标签使用数（未使用、只用 1 次），专题覆盖，无 `references` 与 `reviewedAt` 过期的题；题库有校验错误时也能出报告 |
| `bank-spec merge-question` / `remove-question` | 合并 / 删除题目并改写全部引用与生命周期（§4） |
| `bank-spec export --format anki` | 导出 Anki 牌组（预留） |

校验项：front matter 字段与取值；分段名称、顺序、必填与长度；要点 / 追问 id 唯一且不复用；代码块语言标注与行数；资源存在且格式为 PNG / JPEG / WebP、单张 ≤ 1 MB；`related` / `prerequisites` / `collections` 引用存在、`prerequisites` 无环；标签父子无环；生命周期完整（消失的 id 必须声明）；`version` 相对上一版递增；正文不得出现 HTML。

发布 JSON Schema（`bundle.schema.json`、`latest.schema.json`、`front-matter.schema.json`，位于 `packages/bank-spec/schema/`）供编辑器提示与 App 端复用。

用法（`pnpm bank <command>` 等价于 `node packages/bank-spec/cli.mjs <command>`）：

```bash
bank-spec new      --bank <dir> --category <id> [--title <t>] [--tags a,b]   # 写入 questions/<category>/<id>.md
bank-spec fix-ids  --bank <dir> [--dry-run]
bank-spec validate --bank <dir> [--previous <latest.json>]
bank-spec build    --bank <dir> --out <dist> (--previous <latest.json> | --first-release)
                   [--base-url <url>] [--published-at <iso>] [--pretty]
bank-spec stats    --bank <dir> [--stale-days <n，默认 365>] [--today <YYYY-MM-DD>] [--json]
bank-spec merge-question  --bank <dir> --from <id> --into <id> [--dry-run]
bank-spec remove-question --bank <dir> --id <id> [--dry-run]
```

诊断逐行输出 `file:line: CODE message`（警告为 `file:line: warning CODE message`）；有错误时退出码为 1，`build` 不写任何产物。警告不阻止构建：`详解` 超长、`## 题目` 中写出处、未被引用的资源文件、残留 `TODO`、核心要点超过 2 条（`KEYPOINT_CORE_COUNT`）、标签超过两层（`TAG_DEPTH`）。

- `--previous` 只接受本地文件。CI 发版时先下载上一版：`curl -fsSL -o previous.json <bank.update.manifest>`；下载失败必须让任务失败，不得退回 `--first-release`。
- 独立使用（如题库仓库 CI）：`packages/bank-spec` 自带最小 `package.json`（唯一依赖 `yaml`，版本锁定），在该目录 `npm install --omit=dev` 后即可 `node cli.mjs …`。示例题库与其构建产物见 `packages/bank-spec/examples/`。

## 6. App 存储格式（SQLite，内部实现）

> 不属于对外契约，此处为设计约定，可随 App 版本演进。

### 6.1 题库数据（安装 / 更新时整库替换）

```sql
CREATE TABLE banks (
  id TEXT PRIMARY KEY,               -- bank.id
  origin TEXT NOT NULL,              -- 'remote' | 'local'（用户自建）
  name TEXT NOT NULL, version TEXT, locale TEXT,
  manifest_url TEXT, fallback_url TEXT, feedback_url TEXT,
  installed_at INTEGER, checked_at INTEGER, check_result TEXT
);
CREATE TABLE questions (
  bank_id TEXT NOT NULL, id TEXT NOT NULL,
  title TEXT NOT NULL, type TEXT, difficulty TEXT, importance INTEGER,
  category_id TEXT, summary TEXT,
  data TEXT NOT NULL,                -- 该题完整 JSON（bundle 中的对象）
  content_hash TEXT NOT NULL,
  PRIMARY KEY (bank_id, id)
);
CREATE TABLE question_tags (bank_id TEXT, question_id TEXT, tag_id TEXT, PRIMARY KEY (bank_id, question_id, tag_id));
CREATE TABLE categories (bank_id TEXT, id TEXT, name TEXT, sort INTEGER, PRIMARY KEY (bank_id, id));
CREATE TABLE tags (bank_id TEXT, id TEXT, name TEXT, parent_id TEXT, PRIMARY KEY (bank_id, id));
CREATE TABLE collections (bank_id TEXT, id TEXT, name TEXT, description TEXT, question_ids TEXT, PRIMARY KEY (bank_id, id));
CREATE TABLE lifecycle (bank_id TEXT, question_id TEXT, kind TEXT, target_id TEXT, PRIMARY KEY (bank_id, question_id));
-- 全文搜索：标题、一句话、要点、详解、追问。expo-sqlite 57 在 Android 默认启用 FTS5，内置 SQLite 3.50 支持 trigram。
-- 查询 ≥ 3 字走 FTS5 trigram；1–2 字（如「事务」）退回对同一表的 LIKE 扫描。
CREATE VIRTUAL TABLE question_fts USING fts5(bank_id UNINDEXED, question_id UNINDEXED, title, body, tokenize = 'trigram');
```

- **更新 = 单个事务内删除该 `bank_id` 的全部题库行并插入新数据**，失败整体回滚；学习数据表不参与。
- 列表、筛选、搜索只读冗余列与 FTS；详情页读 `data` JSON。
- 用户自建题库 `origin = 'local'`，编辑单题只更新一行；「导出」即按 §3.2 生成 `bundle.json`，与官方题库同格式，可分享、可再导入。

### 6.2 学习数据（永不随题库更新删除）

```sql
CREATE TABLE progress (
  bank_id TEXT, question_id TEXT,
  mastery TEXT,                      -- unknown | fuzzy | known
  streak INTEGER, due_at INTEGER, marked_at INTEGER,
  seen_hash TEXT,                    -- 上次学习时的 content_hash，用于「内容已更新」提示
  viewed_at INTEGER,
  PRIMARY KEY (bank_id, question_id)
);
CREATE TABLE keypoint_checks (bank_id TEXT, question_id TEXT, keypoint_id TEXT, checked_at INTEGER, covered INTEGER,
  PRIMARY KEY (bank_id, question_id, keypoint_id, checked_at));
CREATE TABLE followup_progress (bank_id TEXT, question_id TEXT, followup_id TEXT, mastery TEXT, PRIMARY KEY (bank_id, question_id, followup_id));
CREATE TABLE favorites (bank_id TEXT, question_id TEXT, created_at INTEGER, PRIMARY KEY (bank_id, question_id));
-- 个人笔记（暂缓，见 §8）：notes(bank_id, question_id, target, body, updated_at)，target = 'question' | 'kp:<id>' | 'f:<id>' | 'my-answer'
CREATE TABLE sessions (bank_id TEXT PRIMARY KEY, queue TEXT, idx INTEGER, mode TEXT, title TEXT, updated_at INTEGER);
-- 自定义分区（issue #3）：用户在分类之上建的个人目录，只引用分类 id，不改题库
CREATE TABLE user_sections (bank_id TEXT, id TEXT, name TEXT, sort INTEGER, created_at INTEGER, PRIMARY KEY (bank_id, id));
CREATE TABLE user_section_categories (bank_id TEXT, section_id TEXT, category_id TEXT, sort INTEGER,
  PRIMARY KEY (bank_id, section_id, category_id));
```

- 安装 / 更新后按 `lifecycle` 迁移：`merged` 的学习数据并入目标题，`removed` 的标记为归档。
- 自定义分区引用的分类在题库更新后消失时，分区保留、该分类显示为「已不在题库中」并可移除。
- 备份 = 导出学习数据表（加本地自建题库的 bundle）；恢复时按 `(bank_id, question_id)` 合并，较新的记录胜出。

### 6.3 实现补充（App 0.2，`src/bank/db/schema.ts` 为准）

- 版本化迁移记在 `PRAGMA user_version`；上表为设计骨架，实际表另含：`banks.origin` 增加 `'file'`（文件导入、无更新地址，只读），
  `banks.meta / description / asset_dir / assets_sha256 / published_at / updated_at`；`questions.sort`（bundle 内顺序）；
  `categories / tags` 的 `sort`、`position`，`collections.position`；`progress.archived_at`（lifecycle.removed 归档）与 `updated_at`、
  `favorites.archived_at`、`followup_progress.updated_at`、`user_sections.updated_at`（备份合并「较新者胜出」的依据）；
  `app_settings(key, value)` 存当前题库与本地题库的要点 / 追问编号计数器。
- 本地自建题库 id 为 `local/device/<ULID>`。

## 7. 预留功能与对应字段

| 功能 | 依赖字段 | 说明 |
|---|---|---|
| 按要点自评 | `keyPoints[].id/weight` | 掌握度由覆盖要点的加权比例决定；可升级 FSRS 等复习算法 |
| AI 模拟面试 | `summary`、`keyPoints`、`pitfalls`、`followups` | 按「出题 → 作答 → 追问」进行，以要点与易错点为评分依据 |
| 快速复习 | `summary`、`keyPoints` | 每题只看一句话与要点 |
| 每日推荐 | `importance`、`progress.due_at`、`keypoint_checks` | 到期 + 高频 + 薄弱要点优先 |
| 专题 / 学习路径 | `collections`、`prerequisites` | 有序题单；不会某题时提示先学前置题 |
| 内容纠错 | `feedbackUrl` | 每题「内容有误」入口，自动带题目 id |
| 内容时效 | `appliesTo`、`reviewedAt`、`references` | 显示适用版本；作者端列出久未复核的题 |
| 更新说明 | `latest.json.changes`、`contentHash` | 更新前展示变化，更新后标记改过的题 |
| 选择 / 判断题 | `type: choice`、`choice` | 客观判分的快速自测 |
| 导出 Anki / 分享单题 | 结构化字段 | 由 bundle 直接转换 |
| 多语言 | `bank.locale` | 一库一语言；多语言用多个题库 |

## 8. 决议与暂缓项（2026-11-05）

| 议题 | 决议 |
|---|---|
| `bank.id` 形式 | 采用 `<host>/<owner>/<repo>`。仓库改名的处理暂不设计，需要时在 `latest.json` 增加 `movedTo` |
| 分发压缩 | `bundle.json` 不压缩（数千题量级仍在数 MB 内），App 无需引入解压库 |
| 全文搜索 | FTS5 + trigram；1–2 字查询退回 LIKE |
| 分册 | 一库一版本；分册用 `collections` + `categories` 表达，不设独立版本 |
| 旧数据 | v2 App 不读取旧版 App 的任何本地数据，全部从零开始 |
| 自定义分区（issue #3） | 纳入 v2，属于学习数据层（§6.2 `user_sections`） |
| 国内镜像 | **暂缓**：`latest.json` 保留 `mirrors` 字段，构建工具暂不生成镜像地址 |
| 个人笔记 | **暂缓**：表结构预留在 §6.2 注释中，本期不实现 |
| AI 辅助理解（issue #4） | **暂缓**：需求未定；`summary` / `keyPoints` / `detail` / `pitfalls` 已可作为 AI 输入，本期不实现 |
| contentHash 范围（2026-11-08） | 只算内容字段（§3.2）；元数据批量调整不触发「内容已更新」 |
| 日常校验与发版（2026-11-08） | `validate` 不查版本递增；`build` 必须 `--previous` 或显式 `--first-release` |
| 首发与 v1（2026-11-08） | v2.0.0 发布前官方 `latest.json` 为 404，App 显示加载失败；v2 成为 Latest 后 v1 App 无法再更新题库。v1 不兼容、不提供占位包，v1 用户需升级 App |
| 题型扩展（2026-11-08） | 场景 / 代码 / 设计 / 行为题目前用现有字段承载，只用于阅读与自评；可执行测试用例、结构化评分（rubric）需要时再扩展规范、构建工具与 App |
