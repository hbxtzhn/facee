# FaceE 题库规范 v1

> 配套：[`FaceE-实现方案.md`](./FaceE-实现方案.md)
> 目标：让"题库作者"与"App 解析器"之间有一份可校验、无歧义的契约。App 端所有校验规则都能在本规范里找到对应条款，反之亦然。
> 兼容基线：PRD `pre.md` §16–§23 的全部要求；本文档在其上做三处扩展（追问文件、关联题语法、`schemaVersion`），扩展均为**可选**，即 PRD 最小题库可以直接被 v1 解析器接受。

---

## 1. 题库包（ZIP）要求

| 项 | 要求 |
|---|---|
| 格式 | 标准 ZIP（Deflate 或 Store），**不允许加密** |
| 编码 | 条目名 UTF-8（必须设置 EFS/bit 11；若无则按 GBK 回退并告警） |
| 顶层 | `catalog.json` 位于包根，**或**位于唯一的顶层目录下（GitHub `codeload` 导出的 `<repo>-<branch>/` 形态自动兼容） |
| 路径 | 全部使用 `/` 分隔；禁止绝对路径、`..`、空段、盘符、控制字符；禁止符号链接条目 |
| 重复 | 不允许重复条目（大小写不敏感比较） |
| 规模 | 条目数 ≤ 50 000；单文件解压后 ≤ 64MB；总解压后 ≤ 2GB |
| 必须包含 | `catalog.json`；`catalog.json` 中每道题声明的 `question.md` |
| 可包含 | `answer.md`、`followups.md`、`assets/**`、`README.md`、`LICENSE` |
| 其他文件 | 允许存在但会被忽略（不参与校验），例如 `.github/**`、编辑器临时文件（以 `.` 或 `_` 开头的忽略规则见 §6） |

### 1.1 解析与解压约定（v1 明确化）

| 约定 | 说明 |
|---|---|
| 解压执行方 | 由 **App 自身的 JS 层**按中央目录白名单逐条目解压并写盘（方案 §7 的 G3）。因此包内**不得**依赖第三方工具的特殊行为，也**不允许**符号链接、设备文件、目录属性条目等非普通文件 |
| 中央目录必须完整 | 允许条目设置“数据描述符”（通用位 bit 3），但不允许中央目录缺失/截断 |
| 压缩方式 | 仅 `Store(0)` 与 `Deflate(8)`；其他方式（bzip2/LZMA/Zstd 等）拒绝 |
| 文件名编码 | UTF-8 并设置 EFS 位（bit 11）；未设置则按 GBK 回退并告警 |
| 写入路径 | 输出路径 = staging 目录 + 规范化后的相对路径，且必须断言仍位于 staging 内；路径穿越不可能发生，但依然按“拒绝”处理 |
| 校验顺序 | 预检（不解压）→ 校验清单全部通过 → 才开始写盘，避免“先写入再发现非法”的浪费 |

## 2. 目录结构

```
<题库根>/
├─ catalog.json               # 必填
├─ README.md                  # 选填
├─ questions/
│  ├─ spring-tx-01/
│  │  ├─ question.md          # 必填
│  │  ├─ answer.md            # 选填
│  │  ├─ followups.md         # 选填（★v1 扩展）
│  │  └─ assets/              # 选填
│  │     └─ architecture.png
│  └─ jvm-gc-01/
│     ├─ question.md
│     └─ ...
└─ （忽略：.git/、.github/、node_modules/、任意 .*）
```

**硬规则**

1. 题目目录名 **必须等于** 题目 `id`（§18：ID 用于定位，目录名参与定位）。
2. 题目目录必须直接位于 `questions/` 之下，**不支持嵌套分类目录**（分类关系由 `catalog.json` 的 `categoryId` 表达，避免两处定义同一事实）。
3. 题目目录内除 `question.md`、`answer.md`、`followups.md`、`assets/**` 之外的额外文件会被忽略（不阻断）。

### 3.2 字段表

#### `schemaVersion`（number，必填）
恒为 `1`。未来不兼容变更时递增；解析器遇到未知版本**必须拒绝安装**（`E_CATALOG_SCHEMA`）。

#### `bank`（object，必填）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `id` | string | ✅ | `^[a-z0-9][a-z0-9-]{0,63}$` |
| `name` | string | ✅ | 1–60 字，App 展示名（§14.2） |
| `version` | string | ✅ | 建议 SemVer；参与 `versionKey` 与"已安装/可更新"判断 |
| `updatedAt` | string | ✅ | ISO-8601 UTC；App 展示"最近更新时间"（§14.2） |
| `description` | string | ❌ | ≤ 200 字 |
| `homepage` | string | ❌ | URL |

在线更新仅按版本判断：发布内容变化时递增 `bank.version`，相同或更低数字版本不替换本地题库。
GitHub Release 下载地址会查询最新正式发布；Release tag 应与包内版本一致（可加 `v` 前缀），ZIP 资产名建议保持固定。
普通 ZIP / 分支归档地址在下载后比较包内版本；未提供版本的旧格式题库保持原来的更新行为。

#### `categories[]`（必填，≥1）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `id` | string | ✅ | `^[a-z0-9][a-z0-9-]{0,63}$`，全库唯一 |
| `name` | string | ✅ | 1–30 字（§5.1 展示） |
| `order` | number | ❌ | 默认 `1000`；排序见 §7 |
| `description` | string | ❌ | ≤ 120 字 |

`categoryId` 为**单值**：一题恰属一个分类（§7.1"所属分类"为单数）。分类**不嵌套**。

#### `tags[]`（必填，可为空数组）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `id` | string | ✅ | `^[a-z0-9][a-z0-9-]{0,63}$`，全库唯一 |
| `name` | string | ✅ | 1–30 字 |
| `parentId` | string \| null | ✅ | 必须指向存在的 `tags[].id`；**禁止成环**（§22、§24"非法父子标签关系"） |
| `order` | number | ❌ | 默认 `1000` |

层级深度建议 ≤ 5。父标签筛选**自动包含全部子孙**（§6.4、§22）：`filter(q) ∩ tagsSubtree(parent)`。

#### `questions[]`（必填，≥1）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `id` | string | ✅ | `^[a-z0-9][a-z0-9._-]{0,63}$`，全库唯一，**必须等于目录名**（§18） |
| `title` | string | ✅ | 1–200 字；与 `question.md` 的一级标题不一致时以 catalog 为准并告警 |
| `difficulty` | `"easy"｜"medium"｜"hard"` | ✅ | 对应 UI 的 简单/中等/困难（§6.3） |
| `categoryId` | string | ✅ | 必须存在于 `categories[]` |
| `tags` | string[] | ✅ | 每项必须存在于 `tags[]`（§24"不存在的标签"= 硬失败）；去重，顺序无关 |
| `order` | number | ❌ | 默认 `1000`；同值时按 `id` 升序（§23 稳定排序） |
| `hasAnswer` | boolean | ❌ | 若提供，必须与 `answer.md` 是否存在一致，否则失败（§24 精神：不一致即数据不可信）。安装器始终以**文件系统事实**为准 |
| `followupCount` | number | ❌ | 若提供，必须与 `followups.md` 解析出的条目数一致，否则失败 |
| `estimatedMinutes` | number | ❌ | 供 UI 选填展示，不参与校验逻辑 |

## 4. `question.md`（§19）

- 编码 UTF-8，建议以 `# <题目标题>` 一级标题开头（与 `catalog.title` 一致）。
- 支持的标准 Markdown 元素（§7.2 必须全部正确渲染）：标题、段落、粗体、斜体、列表（有序/无序/嵌套）、引用、分割线、行内代码、代码块（**建议标注语言**以获得高亮）、表格、图片、链接。
- 允许 HTML？**v1 不支持**（渲染器按纯文本处理），避免不可控渲染面。
- 图片引用（§21）：使用相对路径 `./assets/xxx.png`（也接受 `assets/xxx.png`）。引用不存在的资源 → **硬失败** `E_ASSET_MISSING`。

代码块示例：

````markdown
```java
public class Main {
    public static void main(String[] args) { System.out.println("hi"); }
}
```
````

表格示例（§7.2 要求支持）：

```markdown
| 隔离级别 | 脏读 | 不可重复读 |
|---|---|---|
| READ COMMITTED | ✗ | ✓ |
| REPEATABLE READ | ✗ | ✗ |
```

## 5. `answer.md`（§20）

- 选填。不存在 = "当前题目暂无答案"。
- 内容为参考答案 Markdown，渲染规则同 §4。
- **不在此文件中放置追问内容**（v1 规定追问放 `followups.md`，见 §6）。

## 6. `followups.md`（★v1 扩展，落地 §9）

### 6.1 格式

```markdown
## 追问 1：为什么这样设计？

这里是对追问 1 的回答，支持完整 Markdown：

```java
// 代码块会影响标题切分吗？不会，切分基于顶层 H2。
```

## 追问 2：如果数据量增加怎么办？

这里是对追问 2 的回答。

## 追问 3：还有别的方案吗？

对比表格：

| 方案 | 优点 | 缺点 |
|---|---|---|
| A | 简单 | 慢 |
| B | 快 | 复杂 |
```

### 6.2 解析规则（精确到可单测）

1. 以**顶层** H2（`## ` 开头，且不在代码块内）作为切分点；代码块内出现的 `## ` 不切分。
2. 每个 H2 块 = 一个追问条目：
   - **追问句** = H2 标题去掉可选的 `追问 N：` / `追问N：` / `追问 N.` 前缀后的文本；若去掉前缀后为空，则用整段标题。
   - **追问答案** = H2 标题行之后、下一个 H2 之前的内容（完整 Markdown）。
3. `## 面试官追问` 这类"分组标题"若其后**没有**内容直到下一个 H2，则视为分组标题、不产生条目（容忍作者写法）。
4. H1（`# 面试官追问`）作为整体标题被忽略。
5. `followupCount` = 解析出的条目数，由安装器实测推导并写入运行时索引。
6. 文件存在但解析出 0 条 → 告警 `W_FOLLOWUP_EMPTY`（不阻断）。
7. 追问默认折叠（§9），展开状态记入阅读状态（见方案 §10）。

## 7. 排序规则（§23）

```
分类：order 升序 → name 升序 → id 升序
标签同级：order 升序 → name 升序 → id 升序
题目：order 升序 → id 升序（字典序，稳定）
```

准则：**同一题库、同一筛选条件，任何时候打开顺序完全一致**。`order` 缺省统一为 `1000`，保证"没写 order"的题库也有确定顺序。

## 8. 题目关联语法（★v1 扩展，落地 §10）

### 8.1 推荐写法

```markdown
相关题目：[Redis 为什么这么快？](facee://question/redis-cache-01)
```

或等价的相对路径写法：

```markdown
相关题目：[Redis 为什么这么快？](../redis-cache-01/question.md)
```

### 8.2 纯文本兜底写法（兼容 PRD §10 示意）

```markdown
相关题目：Redis 为什么这么快？
```

安装期行为：以 `相关题目` / `相关阅读` / `延伸` / `参考` 等触发词开头的行，若其文本**精确等于**（去空白、去标点后）某道题的 `title`，则该段文本自动变为指向该题的链接；匹配不到 → 原样显示 + 告警 `W_TITLE_REF_UNRESOLVED`。

### 8.3 跳转语义

- 内链跳转是 **push**（保留返回栈），返回时恢复原题阅读状态（滚动位置 / 答案展开 / 追问展开）。
- 目标 ID 不存在 → 告警 `W_REF_DANGLING`，渲染为不可点击文本。

### 8.4 外部链接（§11）

`http://` / `https://` / `mailto:` 链接交给系统浏览器打开；其他未知 scheme 一律按纯文本渲染（安全默认）。

## 9. 校验清单（与安装器错误码一一对应）

安装器按顺序执行；任一 **E_** 失败即拒绝安装，且不影响已安装题库（方案 §6.2）。**W_** 只记入安装报告。

| 检查 | 失败码 |
|---|---|
| EOCD / 中央目录可解析、校验和一致 | `E_ZIP_CORRUPT` |
| 题库根可唯一确定（根目录 或 唯一顶层目录下的 `catalog.json`） | `E_CATALOG_ROOT` |
| 压缩方式为 Store(0) 或 Deflate(8) | `E_ZIP_ILLEGAL_COMPRESSION` |
| 无加密位 | `E_ZIP_ENCRYPTED` |
| 路径无绝对/穿越/盘符/反斜杠/控制字符 | `E_ZIP_PATH_ABSOLUTE` / `E_ZIP_PATH_TRAVERSAL` / `E_ZIP_PATH_ILLEGAL` |
| 无重复条目（大小写不敏感） | `E_ZIP_DUPLICATE_ENTRY` |
| 条目数与体积在限内 | `E_ZIP_TOO_MANY_ENTRIES` / `E_ZIP_TOO_LARGE` |
| 落盘文件集合 == 白名单集合 | `E_EXTRACT_UNEXPECTED_FILE` |
| `catalog.json` 存在且为合法 JSON 对象 | `E_CATALOG_UNPARSABLE` |
| `schemaVersion == 1`、必填字段齐全、枚举合法、类型正确 | `E_CATALOG_SCHEMA` |
| `bank.id/name/version/updatedAt` 合法 | `E_CATALOG_SCHEMA` |
| 分类 ID 唯一 | `E_CATALOG_SCHEMA` |
| 标签 ID 唯一、`parentId` 存在、无环 | `E_TAG_PARENT_UNKNOWN` / `E_TAG_PARENT_CYCLE` |
| 题目 ID 唯一 | `E_ID_DUPLICATE` |
| 题目 ID 正则合法 | `E_ID_ILLEGAL` |
| 题目目录名 == 题目 ID（存在未被声明的 `questions/<dir>/` 即为孤儿目录） | `E_ID_DIR_MISMATCH` |
| 每题 `question.md` 存在 | `E_QUESTION_FILE_MISSING` |
| `hasAnswer` 与文件一致（若声明） | `E_HASANSWER_MISMATCH` |
| `followupCount` 与解析结果一致（若声明） | `E_CATALOG_SCHEMA` |
| `difficulty` 枚举合法 | `E_DIFFICULTY_INVALID` |
| `categoryId` 存在 | `E_CATEGORY_UNKNOWN` |
| `tags[]` 每项存在 | `E_TAG_UNKNOWN` |
| Markdown 中引用的本地图片存在 | `E_ASSET_MISSING` |
| 关联题 ID 存在 | `W_REF_DANGLING` |
| 纯文本关联题标题可解析 | `W_TITLE_REF_UNRESOLVED` |
| `followups.md` 解析出 ≥1 条 | `W_FOLLOWUP_EMPTY` |
| `catalog.title` 与 `question.md` 一级标题一致 | `W_TITLE_MISMATCH` |
| `README.md` 存在 | `W_NO_README`（提示性） |
| 文件名含非 ASCII 字节但未设 EFS 位 | `W_ZIP_ENCODING` |
| 同一 `order` 被多道题使用（合法，仅提示排序回退到 id） | `W_ORDER_DUPLICATE` |
| `assets/` 下存在未被任何 Markdown 引用的图片 | `W_ASSET_UNUSED` |
| 题目 `tags` 数组内有重复项 | `W_TAG_DUPLICATE` |

> **实测修正（重要）**：GitHub 的归档 ZIP（codeload）**从不设置 EFS 位**，因此“未设 EFS 就告警”的实现在真实安装时会刷出上百条无信息量的告警。规范收敛为：**仅当文件名确实包含非 ASCII 字节**且未设 EFS 时才告警。同时归档 ZIP **包含目录条目**（以 `/` 结尾），解析时跳过。

## 10. 示例题库与生成器规格（M2 交付）

### 10.1 示例题库（`sample-bank`，用于功能验收）

- 规模：**约 60 题**，分布在 §3.1 的 9 个分类中（每类 5–8 题）。
- 必须覆盖的"特性样例题"（每项至少 1 题，用于逐条验收 PRD）：

| 样例 | 用途 |
|---|---|
| 含全部 Markdown 元素的题 | §7.2 渲染验收 |
| 含代码块（java/sql/js 三种语言） | 代码块与高亮 |
| 含表格 | 表格渲染与横向滚动 |
| 含本地图片（含 1 张宽图 + 1 张长图） | §21 图片解析与全屏查看 |
| 含外部链接 | §11 系统浏览器 |
| 含 3 条追问 | §9 折叠与视觉分层 |
| 无 `answer.md` 的题 | §8 "暂无参考答案" |
| 无 `followups.md` 但有答案的题 | 混合路径 |
| 含 `facee://` 内链（指向 2 道题） | §10 跳转与返回状态恢复 |
| 纯文本关联题（`相关题目：<标题>`） | §8.2 兜底解析 |
| 超长题（≥ 8000 字 + 多个表格） | §28 渲染性能 |
| 纯英文题（1 道） | 搜索大小写不敏感 |
| 中文同音/近形关键词题（≥3 道） | 中文子串搜索召回 |
| 同 `order` 值题（≥2 道） | §23 稳定排序验证 |
| 三层深度标签的题 | §22 父标签含子孙 |

- 题库版本：`bank.version = "1.0.0"`、`1.1.0`（第二个版本用于验证"收藏在换版后保留 + 已删除题隐藏"，§13.1）。

### 10.3 合成压测题库

- 由同一生成器以 `--count 2000` 产出，题目正文由模板 + 变体随机组合（含代码块与表格，逼近真实体量），用于 §28 性能验收。
- 与示例题库分离产出，避免把 2000 题塞进仓库。

### 10.4 生成器接口（CLI 约定）

```bash
# 生成示例题库 + 压缩包
node packages/bank-spec/generate.ts --profile sample --out dist/sample-bank.zip

# 生成 2000 题压测库
node packages/bank-spec/generate.ts --profile stress --count 2000 --out dist/stress-bank.zip

# 生成全部恶意 fixtures
node packages/bank-spec/generate.ts --profile malicious --out dist/fixtures/

# 版本 1.1.0（用于换版/收藏保留验收）
node packages/bank-spec/generate.ts --profile sample --version 1.1.0 --out dist/sample-bank-1.1.0.zip

# 本地"假装是 GitHub"的静态服务
node tools/serve-bank.ts --port 8787 --dir dist
```

验收：上述命令在干净环境下可重复执行、输出确定（同输入同输出字节一致），ZIP 内不含时间戳等非确定性字段。
